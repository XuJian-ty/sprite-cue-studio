# SpriteCue Studio

横版 2D 角色动作、敌人动作、序列帧动画、动作事件、地图编辑工具。

## 当前能力

- PNG 序列和 Sprite Sheet 导入
- 动作类型、连段窗口、触发条件、动作转换关系
- 单键、双键组合触发；默认下跳使用 `S+K`
- 动作段 FPS、PPU、Pivot
- Sprite Sheet 导入时配置帧数、列数、间距、边距、格宽、格高
- 单帧独立时长、序列播放预览
- 动作、动作段、动画帧顺序调整
- 网格、地面线、透明背景
- 空白画布拖拽平移、中键平移、光标中心滚轮缩放
- 左侧动作栏、右侧属性栏、预览区、时间轴可拖动分隔条调整尺寸
- 画布编辑模式：命中范围、特效、Bezier 路径、镜头路径拖拽
- 画布句柄对象筛选、锁定、左右朝向镜像预览
- 路径进度曲线：关键点编辑、画布拖拽、常用预设
- 往返路径下降段直线回收施法者当前锚点
- 命中、物理、特效、音效、速度、镜头轨道
- 可拖动目标、命中检测、受击位移、目标挂点预览
- 命中事件检测范围预览、画布编辑
- 全部事件使用动作时间 Tick，不绑定动画帧
- 时间轴根据事件内部效果自动显示有效长度
- 时间轴播放头直接拖拽，重叠事件可切换为自动换行显示
- 全局撤销、重做，跨动作段事件复制、粘贴、排序、清空
- 配置校验、错误和警告列表、动作段及事件定位
- JSON 导入、导出
- IndexedDB 自动保存最后编辑角色，重新打开工具时恢复项目和编辑资源
- 绑定 Unity 项目并增量同步数据
- 从已绑定 Unity 项目列出并重新打开已同步角色
- 从角色、敌人同步列表安全删除误同步数据及工具生成资源
- 首次同步安装 Embedded UPM Runtime，版本变化时提示更新
- Unity Editor 自动导入角色数据并生成 `FrameActionCharacterAsset`
- 指定 Unity 角色 Prefab 的非破坏性创建或更新
- 独立敌人动作工作区，仅保留地面待机、空中待机、走路、技能、受击类型
- 敌人序列帧、时间轴事件、行为树调用配置和 Unity Prefab 自动同步
- AI 页使用可缩放、可平移的节点画布，支持节点拖动、连接、断开、删除和自动排版
- 独立技能项配置冷却、释放距离、选择权重、移动锁定和朝向锁定
- 内置 Rigidbody2D 巡逻、追击、墙壁检测、悬崖检测和受阻放弃逻辑
- 顶部导航切换角色动作、敌人动作、地图编辑三个独立工作区
- 地图背景、装饰物、碰撞轮廓、遮挡区域、单向平台编辑
- 地图物体支持静态或动态模式；动态物体可配置左右/上下往返、米/秒速度和单程移动范围
- 物体库卡片拖拽摆放、半透明落点预览、逐项默认图层设置
- 地图画布选择、移动、旋转、缩放、左键平移、中键平移、滚轮缩放
- 碰撞画笔多笔续画、端点吸附、自交闭环、交叉成环、草稿管理
- 地图编辑撤销、重做、Delete 删除快捷键、完整地图 JSON 备份恢复
- 地图草稿恢复、Unity 地图数据恢复、指定地图 Prefab 创建或更新
- 角色模块、敌人模块、地图模块分别绑定 Unity 项目并独立同步

## 运行

```powershell
npm install
npm run dev
```

生产模式：

```powershell
npm run build
npm start
```

当前版本只编辑和同步数据，不修改导入图片的像素内容。首次同步会在用户确认后把 Runtime 安装到 Unity 项目的 `Packages/com.frame-action.runtime`。日常配置修改只更新 `Assets/FrameActionData`；底层包版本变化时，工具会单独提示更新 Runtime。

## Unity 接入

1. 未绑定时选择“绑定 Unity 项目”，输入包含 `Assets`、`Packages`、`ProjectSettings` 的项目根目录。
2. 确认安装或更新 Runtime，并完成第一次数据同步。绑定后顶部入口会显示“同步角色”和当前项目名。
3. 在“Unity 角色装配”中填写已有角色 Prefab 的 `Assets/.../*.prefab` 路径；留空时使用工具显示的默认新角色路径。
4. 等待 Unity 导入完成。目标 Prefab 已存在时只更新 Frame Action 组件、角色资源引用、Rigidbody2D、身体碰撞体和独立受击区域；目标不存在时创建完整角色 Prefab。
5. 把该 Prefab 放入测试场景即可验证动作。引用此 Prefab 的既有场景实例会正常获得更新。

已绑定项目可以在连接弹窗中直接同步、重新打开 `Assets/FrameActionData/Characters` 中的角色，也可以更换项目或解除绑定。解除绑定只清除工具保存的项目路径，不会删除 Unity 项目里的 Runtime、同步数据或生成资产。

角色项目连接采用与敌人一致的身份逻辑：可以创建新角色，也可以打开已同步角色继续修改。新角色名称不存在时创建独立记录，同名时先确认是否覆盖；打开的角色按原 JSON 路径更新，修改名称不会新建另一条记录。角色列表也提供带二次确认的删除入口，自动生成 Prefab 会随对应角色清理，项目原有 Prefab 默认保留。

敌人项目连接弹窗的已同步敌人列表提供删除入口。删除前会显示二次确认；确认后清理该敌人的 `Assets/FrameActionData/Enemies` 源数据和 `Assets/FrameActionGenerated/Enemies` 生成资源。工具自动创建的敌人 Prefab 会一起删除，绑定的项目原有 Prefab 会保留，其已有组件不会自动回滚。本地草稿也会保留，重新同步即可再次创建敌人。多个敌人误用同一个 Prefab 时，工具会保留共享 Prefab，并安排剩余敌人重新同步，避免删除一个配置时破坏其它敌人。

敌人名称变化后，如果“目标敌人 Prefab”仍指向另一个工具生成目录，同步时会自动切换到当前敌人的独立生成路径。自定义 Prefab 已被其它敌人配置占用时会停止同步并提示冲突，避免后同步的敌人覆盖先前敌人。

同步同名敌人时会先显示覆盖确认，列出旧数据路径和目标 Prefab。选择“覆盖并同步”才会更新同名记录；取消后 Unity 中的旧数据保持不变。

已同步敌人列表旁提供“创建新敌人”入口。新建状态按名称决定创建或提示覆盖；从列表打开的敌人会记录其 Unity 数据身份，之后即使修改名称也继续更新原记录，不会创建另一个敌人。导入 JSON 只替换当前编辑页面的数据，并保留导入前的“创建新敌人”或“已打开旧敌人”状态。已打开敌人改成另一个现有敌人的名称时会停止同步，避免产生无法区分的同名记录。右上角同步按钮会在文字后显示当前敌人状态。

## 敌人模块

顶部切换到“敌人动作”后，工具使用独立草稿和 Unity 绑定。默认动作包含地面待机、空中待机、走路、技能、受击；左侧“+”每次添加一个独立技能项，每个技能拥有自己的序列帧、时间轴、冷却、最小/最大释放距离、选择权重、移动锁定和朝向锁定。巡逻和追击属于 AI 行为，共用走路动作。敌人不显示键盘鼠标触发、玩家横版驱动、摄像机跟随、连段参数和动作转换表，序列帧、动作段、时间标记及六类时间轴事件保持可用。

“AI”页签会把中间预览区和动作时间轴替换为行为树节点画布。选择器、顺序器可以从底部端口连到其它节点顶部端口；节点可自由拖动，同一父节点下从左到右就是执行优先级，也可以一键自动排版。右侧显示当前节点属性和横向移动参数。默认行为按“释放可用技能 → 追击已发现目标 → 地面巡逻”的优先级运行；目标优先按配置的 Tag 查找，找不到时自动寻找 `FrameActionController2D` 玩家。巡逻碰到墙、悬崖或边界会转身，追击受阻会等待并在超时后放弃目标。该方案只使用 Rigidbody2D，不依赖 A* 或 NavMesh，也不包含跳跃寻路。

受击和眩晕属于 Runtime 全局行动锁，无需放进行为树。敌人收到伤害后会强制播放受击动作，立即停止横向速度并暂停、重置行为树；眩晕状态通过命中事件中的“物理效果 → 眩晕”配置，在持续时间内禁止移动、转身、技能和自定义行为任务。受击动作和眩晕均结束后，行为树从入口重新决策。霸体会保留伤害通知但跳过受击动作，无敌会忽略伤害通知和受击动作。

同步后源数据写入 `Assets/FrameActionData/Enemies`，生成资源写入 `Assets/FrameActionGenerated/Enemies`。目标 Prefab 会获得 `FrameActionPlayer`、`FrameActionEnemyController2D`、`FrameActionEnemyMotor2D`、`FrameActionEnemyBehaviorRunner2D`、`FrameActionBuiltinEventHandler2D`、Dynamic Rigidbody2D、身体碰撞体和独立受击区域；不会挂载玩家输入、玩家运动、角色状态转换或摄像机跟随组件。已有 Prefab 上的项目脚本、子节点和挂点会保留。普通巡逻、追击、技能释放和受击不需要额外编写代码。

常见行为树节点可以直接调用：

```csharp
FrameActionEnemyController2D enemy = GetComponent<FrameActionEnemyController2D>();

enemy.PlayAction("skill-fireball");       // 按唯一动作 ID 播放
enemy.PlayFirstActionOfType("hurt");      // 播放该类型的首个动作
enemy.SetAirborne(true, true);              // 切换为空中状态并播放空中待机

bool running = enemy.IsPlaying;
string current = enemy.CurrentActionId;
```

`PlayAction` 直接切换动作，不读取打断、缓存、忽略关系。`TryPlaySkill` 会校验该技能的距离和独立冷却。行为树可等待 `IsPlaying` 变为 `false`，也可以订阅 `ActionStarted`、`ActionCompleted`。敌人收到 Frame Action 伤害时会自动播放首个受击动作。

工具内置 `hasTarget`、`canUseAnySkill`、`targetDistance`、`targetHorizontalDistance`、`targetVisible`、`grounded`、`blocked` 条件，以及 `patrol`、`chase`、`stop`、`faceTarget`、`useBestSkill` 任务。生命值、阶段切换、召唤控制等项目专用逻辑仍可通过 `IFrameActionEnemyBehaviorAdapter` 扩展。适配组件放在敌人根节点即可被自动发现，也可以拖到 `FrameActionEnemyBehaviorRunner2D.adapterBehaviour`：

```csharp
public sealed class EnemyBlackboardAdapter : MonoBehaviour, IFrameActionEnemyBehaviorAdapter
{
    public Transform currentTarget;

    public bool EvaluateCondition(string key, string comparison, float numberValue, string stringValue)
    {
        // 从项目目标系统、生命组件或寻路代理读取数据并完成比较。
        return key == "hasTarget" && currentTarget != null;
    }

    public FrameActionEnemyBehaviorStatus ExecuteTask(string key, float numberValue, string stringValue)
    {
        // 启动或推进追击、巡逻等异步任务，返回 Running / Success / Failure。
        return FrameActionEnemyBehaviorStatus.Running;
    }

    public void ResetTask(string key) { /* 分支结束时停止该任务 */ }
}
```

## 地图接入

顶部切换到“地图编辑”后，地图模块使用自己的项目连接和同步入口。它不会读取或修改角色模块的绑定状态；两个模块可以绑定同一个 Unity 项目，也可以分别绑定不同项目。

- 角色项目路径保存在 `frameAction.unityProjectPath`。
- 敌人项目路径保存在 `frameAction.enemyUnityProjectPath`。
- 地图项目路径保存在 `frameAction.mapUnityProjectPath`。
- 地图源数据写入 `Assets/FrameActionData/Maps`。
- 地图 Prefab 写入 `Assets/FrameActionGenerated/Maps`，也可以绑定已有地图 Prefab 进行更新。
- 地图同步只处理当前地图数据、地图素材和目标地图 Prefab，不会修改角色 Prefab。

地图项目连接采用记录身份：创建新地图时，不同名称会建立独立数据目录和 Prefab；同名时先显示覆盖确认。从“打开已同步地图”载入后，后续同步始终更新原 JSON，修改地图名称不会另建记录。导入 JSON 只替换当前页面数据，继续保留“创建新地图”或“已打开旧地图”状态。列表旁的删除入口会清理该地图的同步数据、归档背景和工具生成 Prefab，项目原有 Prefab 默认保留。

新地图目录使用名称摘要避免相近中文名称发生路径碰撞。已存在的旧地图继续沿用原目录，打开、改名和更新时不会迁移其身份路径。

### 工具自动处理

- 校验所选目录是否为 Unity 项目。
- 首次确认后安装 Embedded UPM Runtime，版本变化时提示更新。
- 将当前角色 JSON、引用到的角色图片、特效图片和音频增量写入 `Assets/FrameActionData`。
- Unity 检测到同步数据后自动创建或更新 `FrameActionCharacterAsset`。
- 自动设置同步图片的 Sprite 类型、PPU、Pivot、透明通道和 Mipmap，并建立资源 ID 绑定。
- 按“目标角色 Prefab”更新指定角色；保留现有其它脚本、子节点、挂点和用户组件，路径不存在时才创建新 Prefab。
- 根据工具中的身体碰撞体、独立 Trigger 受击区域和刚体质量更新角色装配。
- Runtime 负责序列帧播放、动作时间轴推进、事件触发、命中检测、统一受伤入口、通用状态和受击动作请求。
- 物理轨道的“瞬移”效果以自身或当前目标为锚点。距离正数位于锚点前方，负数位于锚点后方；Runtime 自动执行地面贴合、墙体阻挡、落点修正和速度清理。敌人以目标为锚点时会在落点自动面向目标。
- 标准角色驱动使用 Unity New Input System，按动作触发配置生成键盘、键盘组合、鼠标、方向键和手柄输入。走路与跑步速度保存在对应移动动作中，跳跃高度保存在各跳跃动作段中。
- 默认下跳动作只在角色站于 `PlatformEffector2D` 单向平台时生效。Runtime 临时忽略脚下平台碰撞，角色完全穿过表面后自动恢复；普通实体地面不会响应。
- Runtime 内置局部 VFX/SFX 对象池，动作结束或效果到期后统一回收，避免时间轴反复创建临时对象。
- `Setup Selected Character` 继续支持未绑定 Prefab 的临时场景对象；通过工具同步的目标 Prefab 不需要再执行该命令。

### Unity 手动配置

- 正式场景使用工具中明确绑定的角色 Prefab；工具不会创建测试场景、测试目标、相机或地面。
- 配置角色 Layer、命中 Layer 和 Physics 2D 碰撞矩阵，使命中事件能找到正确目标。
- 没有 Prefab 的临时场景对象可执行一次 `Tools/Frame Action/Setup Selected Character`；绑定 Prefab 已自动完成这些引用。
- 默认输入或运动不符合项目需求时，关闭“启用标准输入”或“启用标准运动”，由 AI、网络或自定义控制器调用统一命令入口。
- 编写生命值、护盾、防御、死亡、阵营等玩法组件，并订阅 `DamageReceived` 进行实际扣血。
- 敌人移动组件会自动向时间轴提供行为树当前目标。其它自定义控制对象使用目标锚点时，需要配置 `defaultTarget` 或实现 `IFrameActionTargetProvider`。

配置命令会安装播放、状态控制、输入、运动和事件组件。标准实现只处理横版动作游戏通用行为，项目仍可替换输入源或运动层。生命值、伤害公式、阵营、掉落、AI 决策等玩法不会写进 Runtime。扩展接口如下：

- `IFrameActionDamageReceiver`：接收命中伤害倍率、命中点。
- `IFrameActionStatusReceiver`：接收眩晕、霸体、无敌状态。
- `IFrameActionCameraReceiver`：接收镜头偏移、缩放和区间进度。
- `IFrameActionTargetProvider`：按项目规则返回当前目标。
- `IFrameActionHitStopReceiver`：接收命中停顿状态。
- `IFrameActionCommandSink`：接收移动轴、动作 ID 和自定义命令，供 AI、网络或项目输入层复用。

### Runtime 分层

- `FrameActionInputDriver2D`：采集本地输入，也接受 AI、网络和测试代码提交的命令。
- `FrameActionController2D`：执行动作切换策略、缓存请求、动作段选择、地面/空中入口和通用状态。
- `FrameActionMotor2D`：执行 Rigidbody2D 走跑、加减速、空中控制、跳跃缓冲、离地宽限、多段跳和朝向。
- `FrameActionPlayer`：播放帧动画，按 Tick 推进数据时间轴，计算施法速度和运动速度倍率。
- `FrameActionBuiltinEventHandler2D`：执行命中、物理、特效、音效、镜头和命中停顿。

项目自有输入可保留 `FrameActionInputDriver2D` 作为命令入口，并将 `acceptLocalInput` 关闭：

```csharp
inputDriver.SubmitMoveAxis(aiMoveX);
inputDriver.TriggerAction("attack");
inputDriver.TriggerCustom("Skill1");
```

这种接入不会绕过动作转换关系。玩家输入、敌人 AI、回放和网络同步最终都进入同一个数据驱动控制器。

`FrameActionController2D` 已实现 `IFrameActionDamageReceiver` 和 `IFrameActionStatusReceiver`。同步角色会获得独立的 `FrameActionHurtbox2D` Trigger；存在该组件时命中检测只接受受击区域，身体碰撞体继续负责地面和墙体接触。未安装 Hurtbox 的外部角色仍会使用原 Collider2D。命中后 Runtime 向父对象查找统一入口，触发 `DamageReceived`，随后自动播放触发类型为“受到伤害”的动作。眩晕会临时阻止动作和标准移动，霸体会保留伤害通知但跳过受击动作，无敌会忽略伤害通知。项目生命系统可以订阅事件，根据攻击者属性、伤害倍率计算实际扣血：

```csharp
private void OnEnable()
{
    controller.DamageReceived += HandleDamage;
}

private void HandleDamage(FrameActionDamageContext context)
{
    health.ApplyDamage(baseAttack * context.multiplier);
}
```

陷阱、场景伤害、网络同步等外部系统可以调用 `controller.NotifyDamaged(...)`，经过相同的受击入口。玩家角色继续使用 `FrameActionController2D` 的自动受击动作；敌人模块使用 `FrameActionEnemyController2D`，由行为树或敌人生命组件在收到伤害后调用受击动作 ID。

Runtime 不区分主角受伤方法和敌人受伤方法。任何角色只要实现 `IFrameActionDamageReceiver`，就能接收主角、敌人、陷阱或网络层发来的统一伤害上下文。默认的 `FrameActionController2D` 已经实现该接口，所以双方不需要直接引用或调用对方的具体脚本。框架只负责命中通知、受击动作触发和通用表现；生命值、护盾、防御、死亡、阵营等玩法仍由 Unity 项目代码处理。即使项目暂时没有生命值组件，命中调用和受击动作仍然可以执行，只是不会产生实际扣血。

攻击数据中的命中特效、命中音效由攻击者的时间轴在实际命中点播放。敌人自身特有的受击动画、音效、特效可以配置在敌人的受击动作中，因此同一种攻击命中不同敌人时，各敌人仍能表现自己的受击反馈。

## 字段边界

- 命中检测方式分为范围检测、射线检测、物理实体。
- 范围检测支持自身、目标、世界锚点；目标锚点在检测期间跟随当前锁定目标。
- 物理实体支持自身、目标、世界锚点；锚点只决定生成位置，生成后由 Rigidbody2D 独立运动。
- 普通特效：支持施法者、目标、世界挂点。
- 普通音效：支持施法者、世界挂点。
- 命中特效、命中音效：支持施法者、目标、世界挂点。
- 特效移动设置：仅世界挂点显示。
- 检测体移动设置：仅世界锚点的范围检测、射线检测显示。
- 普通特效、普通音效：非循环时完整播放一次后自然结束；循环时只允许指定时长或动作结束销毁。
- 命中特效、命中音效：固定单次播放，完整播放后自然结束。
- 伴随特效：固定循环播放，随检测体生成、移动、旋转，在检测结束时销毁，不单独配置挂点、跟随时长、销毁方式、移动设置。

## 物理实体

命中效果选择“物理实体”后，Runtime 会从对象池创建带非 Trigger `Collider2D` 和 Dynamic `Rigidbody2D` 的真实游戏对象。实体根节点不渲染图片，盒体或圆形只负责物理碰撞；伴随特效作为子对象提供外观并继承实体的位置、旋转，持续时长结束时一同回收。

物理实体复用范围检测的激活方式、命中去重、锚点、中心位置、旋转、命中伤害、命中物理、命中特效和命中音效。检测时长在该模式下显示为“持续时长”，同时决定实体和伴随特效的存在时间。实体可以跨动作继续存在，重复事件每次触发都会创建独立实例。

世界锚点支持移动设置。直线移动的方向和速度会转换为刚体初速度，随后由 Physics 2D 接管；Bezier 在路径时长内通过刚体移动，路径结束后交给物理模拟。自身锚点不显示移动设置。质量、重力倍率、阻尼、摩擦、弹性、旋转、连续碰撞、初始角速度、继承施法者速度和短暂忽略施法者碰撞均可独立配置。

物理实体只支持盒体和圆形。实体 Layer 需要参与项目的 Physics 2D 碰撞矩阵；需要让角色站在实体上时，应将该 Layer 纳入角色的地面检测。标准角色电机会读取脚下动态刚体的接触点速度，使角色能够随移动或滚动实体运动。实体接触受击区域时会调用与范围检测相同的命中效果链。

## 激活去重

命中去重作用于完整命中效果链，包含伤害、命中物理、命中特效、命中音效和命中停顿。“整个事件”让每个目标在检测事件中最多命中一次；“每次激活”在每个激活轮次开始时重新允许该目标命中一次；“每次检测”会在每次物理检测前清除记录，可能产生很高的命中频率。

间断激活以“激活时长 + 间隔时长”为一个轮次。间隔允许为 `0 Tick`，此时相邻激活轮次首尾相接，Runtime 仍按激活时长划分轮次。例如检测 `300 Tick`、激活 `60 Tick`、间隔 `0 Tick` 会形成 5 个激活轮次。目标只有在相应轮次的检测范围内，才会再次触发命中效果。

## 盒体伸长

范围检测的盒体可以启用“随时间伸长”。盒体宽高仍表示初始尺寸，伸长从命中事件触发时刻开始，按“伸长速度 × 已经过时间”增加对应方向的长度；到达伸长时长后保持最终尺寸，直至检测时长结束。伸长时固定反方向边缘，盒体中心会移动半个新增长度，因此伴随特效也会跟随盒体中心。上下左右使用盒体的局部方向，旋转盒体后伸长方向会一起旋转；角色转向时左右方向会同步镜像。

例如项目为 `600 Tick/秒`，初始宽度 `2`、检测时长 `3000 Tick`、向右伸长速度 `4 米/秒`、伸长时长 `1200 Tick`，则盒体在前 2 秒增加 8 米，最终宽度为 10，之后保持 3 秒。伸长时长超过检测时长时，实际只显示并检测到命中事件结束前的增长部分。画布在任意播放位置显示实时尺寸；拖拽盒体缩放句柄始终修改初始尺寸。

## 特效序列

特效资源以序列帧为主，单张图片会作为单帧序列兼容。每个特效可以导入按文件名排序的 PNG 序列，也可以在专用弹窗中拆分 Sprite Sheet。特效数据保存帧资源列表、播放 FPS、独立 PPU、实例 Pivot、循环状态，不修改原始图片像素。PPU 越大，特效在世界中的基础尺寸越小；界面会根据首帧像素尺寸显示换算后的 Unity 单位大小。Pivot 使用归一化坐标：X 从左到右为 `0~1`，Y 从下到上为 `0~1`，默认中心为 `(0.5, 0.5)`。

普通特效可按用途选择播放方式：挥砍刀光、爆炸、施法闪光使用单次播放；子弹、法球、剑气、持续拖尾使用循环播放。命中特效固定单次播放。伴随特效固定循环，并由命中检测体控制生命周期。

普通特效可以使用目标挂点。持续跟随适合附着效果；启用“限制跟随时长”并设置 `0 Tick` 时，生成瞬间读取目标位置后固定在该世界坐标，适合落雷、预警圈等需要命中目标当前位置、又不应继续追踪移动目标的表现。

同步到 Unity 后，每张特效帧仍按中心 Pivot 导入。Runtime 按当前特效实例的 Pivot 计算位置偏移，直接按配置 FPS 驱动 `SpriteRenderer` 切帧，并把独立 PPU 换算成运行时缩放。同一套序列帧可以被多个特效用不同 PPU、Pivot 复用，配置之间不会互相覆盖，也不依赖 Animator Controller。

## 字段提交

文本和数字字段在输入过程中只保留草稿，按回车或点击输入框外部后才写入项目数据。按 Escape 会放弃本次草稿。位置、方向、命中中心、射线起点、Bezier 控制点、路径终点、镜头偏移和旋转允许输入负小数。距离、高度、半径、尺寸、缩放、速度倍率、持续时间等字段继续遵守各自的非负或正数下限。所有 Tick、帧数、Sheet 行列和像素尺寸使用整数；提交小数后会自动取整。画布拖拽、撤销和重做产生的外部数据变化会直接刷新未聚焦字段。

## 画布编辑

工具栏中的鼠标指针按钮用于开启画布编辑模式。选中时间轴事件后，画布会显示当前事件的编辑句柄：

- 命中范围：移动、旋转、半径或盒体尺寸调整；射线可调整起点、方向、长度、粗细。
- 普通特效、命中特效、伴随特效：Pivot 对齐、移动、旋转、缩放。
- 运动路径：显示 Bezier 曲线、控制点 A、控制点 B、终点，支持直接拖拽。
- 镜头路径：固定点或起点、控制点、终点拖拽。
- 镜头注视：显示当前镜头中心到角色实时枢轴的注视线。

当前事件包含多个范围或特效时，可用画布工具栏下拉框选择编辑对象；锁定按钮只锁定当前事件中下拉框选中的对象，切换到其它对象或其它事件后仍可继续拖拽。锁定状态会保留轮廓和路径显示。

在空白画布按住左键拖拽可平移视图，在任意位置按住中键也可平移。鼠标滚轮以光标位置为中心缩放，角色、目标、特效、命中范围、路径和编辑句柄会一起变化。视图偏移与缩放只影响当前预览，不写入项目数据，不进入撤销历史，也不会同步到 Unity。

目标假人的命中物理预览会累计同一段连续受击产生的位移。最后一个位移效果结束后，假人保持最终位置 2 秒；保持期间再次受到命中物理效果会重新计算倒计时。超过 2 秒未再受到位移效果时，假人回到手动设置的初始位置。

非循环动作自然播放到末尾后会停止并把时间轴播放头复位到开头；手动拖动播放头、使用帧步进或 End 键到达末尾时，播放头会保留在手动位置。从末尾再次点击播放会先从开头重新播放。

左侧动作栏、右侧属性栏支持拖动竖直分隔条调整宽度；预览区和时间轴支持拖动水平分隔条调整高度。分隔条会显示对应的 Resize Cursor，也可聚焦后使用方向键微调。尺寸保存在本地编辑器设置中，不写入角色项目数据。

时间轴红色播放头可以直接抓取拖动，轨道空白区域也支持按住后连续调整播放位置。“重叠事件换行”按钮只改变轨道显示：相同轨道中时间区间重叠的事件会自动分配到下一行，关闭后恢复单行叠放。该开关不会调整事件顺序、触发 Tick 或导出数据。

动作播放长度只由当前动作段的全部动画帧 Tick 总和决定，用于自然结束、循环周期，以及明确配置为“持续到动作结束”或“动作结束销毁”的效果。事件和编辑器的最小显示范围不会延长动作播放。

一次性命中、物理、特效、音效事件没有额外的事件长度字段。时间轴根据直属数据计算事件有效长度：命中事件只取检测时长，不计算命中物理、命中特效、命中音效等命中后效果；激活时刻位于检测窗口内部，限制在 `0~检测时长`，不会重复增加长度。检测时长为 0 时，激活时刻也固定为 0，在事件触发时立即检测一次。物理使用效果持续时间，特效使用序列帧自然播放或销毁时间，音效使用音频长度或循环销毁时间。重复事件的显示宽度延伸到最后一次触发的直属效果结束位置。

动画帧总长仍是动作本身的长度，动作完成回调、连招衔接和“持续到动作结束”均以该长度为准。编辑时间轴拥有独立的显示长度，事件可以放在最后一帧之后；Runtime 会为每次动作播放建立独立事件调度，普通延迟事件和固定时长事件可在动作结束或后续动作开始后继续触发、继续执行。绑定“动作结束”的循环特效、循环音效、物理、速度和镜头仍在原动作末尾停止。时间轴右侧固定预留 `300 Tick` 编辑空间，事件移入预留区域后时间轴会继续向后扩展。

时间轴显示范围取动作播放长度与最晚事件结束时刻的较大值，并至少显示 `300 Tick`；`300 Tick` 只用于编辑器视野。动作结束不会统一终止已创建的独立实例：命中检测区域可以跨动作继续存在，伴随特效会继续跟随检测区域，单次特效和音效会自然结束。只有明确绑定动作结束的效果会在所属动作执行结束时取消。循环动作的每轮播放拥有独立执行编号，上一轮尚未结束的事件实例可与下一轮实例重叠。

时间标记是编辑辅助数据，可用于标记前摇结束、命中峰值、收招开始等关键时刻，事件拖动时会吸附到标记。时间标记不会触发游戏逻辑。

## 路径进度

运动路径和镜头路径都支持归一化进度曲线。横轴是路径时间 `0~1`，纵轴是路径进度 `0~1`。可拖拽关键点、输入数值、添加或删除中间点，并为关键点选择平滑、线性、平直切线，也可使用匀速、加速、减速、缓入缓出、往返预设。画布预览、Unity Runtime 使用同一组曲线数据。

Bezier 运动可启用“下降段回收至施法者当前位置锚点”。命中检测体会回收到施法者当前的中心或射线起点锚点；世界特效会回收到施法者当前位置叠加该特效局部偏移的位置。曲线进入下降段后，运动对象从已经到达的最远点直线回到这个动态锚点，适合回旋镖和回收法球。

## 朝向镜像

动作数据始终按角色朝右的局部坐标保存。预览切换朝左或 Runtime 的 `FrameActionPlayer.facingLeft` 为真时，命中中心、扇形开口、射线方向、特效图片朝向、特效偏移和旋转、直线运动、Bezier 路径、伴随特效、镜头 X 偏移会使用同一规则镜像。自身锚点的范围检测会继续跟随角色当前的位置和朝向；素材自身朝向只决定角色 Sprite 是否翻转，不改变事件数据。

## 速度倍率

`施法速度倍率`直接缩放当前动作的动画播放速度、动作时间轴推进速度。例如设为 `2`，动画和事件时间整体快一倍；设为 `0.5`，整体慢一半。

`运动速度倍率`由标准 `FrameActionMotor2D` 自动消费，用来缩放水平移动、跳跃和下落；它不会改变动画或事件触发时间。关闭标准运动后，项目移动代码仍可读取 `FrameActionPlayer.CurrentMovementSpeedMultiplier` 获得同一数据。

## 音效挂点

- `施法者`：音源跟随当前动作角色，适合脚步、挥砍、角色自身发声。
- `目标`：音源跟随当前目标；命中音效会优先跟随实际被检测到的对象。
- `世界`：触发时记录世界坐标，之后不跟随角色或目标，适合落雷、爆炸、场景机关。

目标挂点没有可用目标时会回退到施法者位置。画布中的蓝色目标只用于外部编辑器预览，不会写入 Unity 场景。

## 运行时架构

`FrameActionStateMachine2D` 将每个动作段视为一个数据状态，由 `FrameActionController2D` 负责接收输入、受击和移动意图。状态机统一消费动作转换表中的 `Interrupt`、`Buffer`、`Ignore`，公开 `CurrentState`、`PreviousState`、`PendingRequest` 及进入、退出、完成生命周期事件。缓存只保留最后一次请求，动作完成时优先消费；新增动作仍通过工具配置，无需在 Runtime 中增加对应的攻击状态类。外部代码直接调用 `FrameActionPlayer.Play(...)` 时，控制器会同步当前状态和上一个状态；正常角色逻辑仍建议通过 `FrameActionController2D.RequestAction(...)` 进入完整转换流程。

`FrameActionRuntimePool` 为特效、音效、物理实体维护独立池，默认容量分别为 96、48、32。`IFrameActionPoolable` 提供获取、回收回调，`SetCapacity`、`Prewarm`、`Clear`、`GetStats` 用于预热、容量控制和诊断。延迟回收携带复用代次，旧协程无法回收或继续改写已经再次取出的对象；超过容量的实例会直接销毁。

桌面快捷方式调用 `scripts/start-sprite-cue-studio.ps1`，会隐藏启动本地服务并打开 `http://127.0.0.1:5188`。
